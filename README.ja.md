*Nunsseop*(눈썹)は韓国語で*眉*、画面の上にある小さなアーチのことです。無料のオープンソースで、アカウントも、サブスクリプションも、トラッキングもありません。

## 30秒でインストール

**[Nunsseop.dmg をダウンロード](https://github.com/namekun/Nunsseop/releases/latest/download/Nunsseop.dmg)** し、開いて Nunsseop をアプリケーションにドラッグしてください。Apple の署名と公証を受けたアプリなので、すぐに開けます。新しいバージョンが出ると、設定 › 一般 › アップデートの「アップデートをインストール」が新しい点を表示し、インストールして Nunsseop を再起動します(0.38.0 より前のアプリは、新しい DMG をもう一度ダウンロードしてください)。

[Homebrew](https://brew.sh) でもインストールできます:

```sh
brew install --cask namekun/tap/nunsseop
```

アップデートは `brew update && brew upgrade --cask nunsseop` で行えます。新しいバージョンが出ると、設定 › 一般 › アップデートでそのコマンドをクリップボードにコピーできます。

macOS 14 Sonoma 以降が必要です。Apple シリコン搭載の Mac に対応し（Intel は非対応）、ノッチのない画面でも動作します。

## 最初の1分

1. **ノッチにポインタを重ねます。** ノッチが開きます。ポインタを離すと、自然に閉じます。
2. ミュージック、Spotify、YouTube Music、またはブラウザで**何か再生してみてください。** ノッチが曲を検出し、閉じた状態でも小さなアートワークとビジュアライザが表示されます。
3. **ノッチを右クリック → 設定**で、タブとその並び順、表示したいポップアップ、サイズを選べます。

Dock にアイコンは出ません。Nunsseop はノッチの中にいます。

初回インストール時は、1 秒ほどでノッチが自動的に開き、4 つの短いステップで案内します。開き方と閉じ方、タブ、ファイルのドロップと検索、この Mac で見つかったエージェントツールの接続です(見つからなければ「準備ができました」で終わります)。「スキップ」、Esc、「完了」で終了でき、設定 › 一般 › 「スタートガイドをもう一度見る」でもう一度表示できます。アップデート後は一度だけ開いてそのバージョンの新機能を伝え、あとは邪魔をしません。

## できること

**🎵 音楽**
- **どのアプリの再生中情報も表示。** ミュージック、Spotify、YouTube Music のほか、Safari、Chrome、Arc、Dia、Aside などのブラウザにも対応します。アートワーク、コントロール、ドラッグできる再生バーを備えています。
- **同期歌詞**を [LRCLIB](https://lrclib.net) から取得し、タイトルの下、または作業中はノッチの下に表示します。
- **スニークピーク。** 曲が切り替わると、タイトルが一瞬だけ滑り出します。
- **ポッドキャストや長い動画**では、プレーヤーが対応していれば、15 秒スキップと再生速度ボタン(1× から 2×)が使えます。

**🗂️ 作業を進める**
- **シェルフ。** ファイルをノッチにドラッグして、あとで取り出せます。画像、PDF、動画のプレビューにも対応し、シェルフの高さに合わせて大きくなります。スクリーンショットや完了したダウンロードを自動で置くこともできます。ファイルをドラッグしながらポインタを振ると、どこにいても、すぐ横に小さなドロップ先が現れます。
- **カレンダーとリマインダー。** 今日の日付を大きな数字で表示し、予定のある日には点が付いた 1 週間、今日の予定、チェックできるリマインダーを表示します。macOS に追加したすべてのアカウント(Google、iCloud、Exchange など)に対応し、表示するカレンダーも選べます。
- **次の予定。** 時刻のある予定が始まる 5 分前に、ノッチにタイトルと開始までの時間が表示されます。Zoom、Google Meet、Teams、Webex、FaceTime、Whereby、Chime のリンクがある予定は、ホームに緑色の「参加」ボタンが出て、通知をクリックするとそのままミーティングに参加できます。
- **Spotlight の代わりになる検索。** アプリ(「アプリケーション」の外にあるものも)、ファイル、システムコマンドと設定、クリップボード履歴、絵文字(`:` から入力)、`12*(3+4)` のような計算に対応し、よく開くものが上位に並びます。頭文字でも検索でき、`vsc` と入力すれば Visual Studio Code が見つかります。矢印キーで選び、Return キーで開きます。
- **自分だけのショートカット。** 検索は初期設定で <kbd>⇧⌘Space</kbd> で開き、好きな組み合わせに変えられます。設定 › 一般 › ショートカットには、最初は空の操作もあります。いちばん長く待っているエージェントへ移動(そのターミナルが前面に出ます)、エージェントタブを開く、最後の通知の送信元へ移動、ノッチを開閉、の 4 つです。ほかの操作がすでに使っている組み合わせは保存されず、macOS や他のアプリがすでに使っている場合は、Nunsseop が知らせてくれます。
- **タイマー、クリップボード履歴、メモ、絵文字ピッカー。** クリップボード履歴はメモリ上にだけ保持され、パスワードマネージャが機密としてマークしたものは記録しません。コピーしたリンクからは、`utm_` や `fbclid` などのトラッキングパラメータが取り除かれます。
- **一覧の横に詳細。** シェルフ、クリップボード、アプリ、検索、通知では、ポインタの下の項目(または ↑ ↓ で選んだ項目)を、操作ボタンとともに右側に表示します。行をクリックすれば、これまでどおりすぐにコピー、起動、または元の場所へ移動します。

**💻 Mac の状態**
- **システム HUD。** 音量、明るさ(DDC 対応の外部ディスプレイを含む)、キーボードバックライト、充電、Caps Lock、AirPods のバッテリーがノッチに表示されます。音量キーと明るさキーを横取りして、システム標準の HUD を出さないようにすることもできます。
- **システム統計とバッテリー。** CPU、メモリ、ディスク、ネットワーク、この Mac のバッテリーをパネルで表示し、さらにマウス、キーボード、トラックパッドの状態も表示。残量が少なくなると警告します。
- **カメラとマイクのインジケータ。** いずれかのアプリが使っている間、ノッチに点が表示されます。
- **ツール。** オーディオ出力の切り替え、アプリごとの音量調整(実験的、macOS 14.2 以降)、マイクのミュート、Mac をスリープさせない、画面収録、ドライブの取り出し、画面上のどこからでも色を拾うカラーピッカー、テキスト取得(画面のどの部分からでもテキストをコピーできます)。
- **天気、ダウンロード、ミラー、Dock のアプリ**も、ポインタを重ねるだけ。天気はホームの一番下の行に出ます。

**📞 閉じている間も**
- **通話。** Zoom、FaceTime、Teams、Slack、Discord、WhatsApp、Google Meet で通話中は、閉じたノッチにアプリ名と通話時間が表示されます。どのアプリがマイクを使っているかで判定するので、デスクトップアプリの通話を表示するのに権限は要りません(ブラウザでの通話は、Meet や Web 版の Zoom・Teams なら、そのブラウザへのオートメーションの許可が必要です)。Zoom、FaceTime、Meet なら、通話画面に切り替えなくても、ノッチからマイクのミュートができ、Zoom と Meet ならカメラのオフもできます(Zoom と FaceTime にはアクセシビリティの許可が、Meet には Chromium 系ブラウザでの「*Apple Events からの JavaScript を許可*」が必要です)。
- **左右に表示する内容を選べます。** 何も再生していないときは、Claude Code や Codex の残り使用量、作業中のエージェント、バッテリー、天気、日付を表示できます。
- **音楽とタイマー。** 音楽の再生中は小さなアートワークとビジュアライザ、タイマーの動作中は残り時間を表示します。タイマー、通話、ダウンロードは左右それぞれを中身に合わせた幅にするので、アイコンだけの側に広い隙間はできません。
- **ダウンロード。** Safari や Chrome のダウンロードの進み具合を、Finder がファイルに表示するのと同じ進捗から、パーセントで表示します。ポーリングはしていません。

**🤖 開発者向け**
- **AI 使用量。** Claude と Codex の上限とリセット時刻、直近 5 時間と 7 日間のトークン使用量を、Claude Code、Codex、gjc、omo、OpenCode をまとめて集計して表示します。これらのツールがすでに Mac に保存しているファイルを読むだけなので、サインインは不要です。上限が 70% に達すると、オレンジ色と「!」で知らせます。
- **Claude Code からの Claude の上限。** 設定 › サービス › AI 使用量で Claude Code のステータスラインを接続します。Claude Code が応答のたびに 5 時間と週の上限を渡してくれるので、作業中も AI タブは最新のまま、Nunsseop が Anthropic に問い合わせることもありません。これまで使っていたステータスラインもそのまま表示され、接続解除で元に戻ります。以前のコマンドを復元できない場合は、設定でお知らせします。
- **Claude の上限をリアルタイム取得(オプトイン)。** 別の場所で Claude を使う場合のために、AI タブで、Claude Code がキーチェーンに保存しているサインイン情報を使い、Claude の 5 時間と週の上限を約 1 時間ごとに Anthropic から取得するかどうかを一度だけ確認します。このサインインは Claude Code の起動時に更新されるため、しばらく使っていないと AI タブは再サインインではなく Claude Code の起動を促します。「はい」と答えるまではオフで、あとから設定 › サービスで変更できます。いちばん新しい取得元が優先され、そこにプランやモデル別のバーがなければ前のものをそのまま表示します。
- **上限アラート。** Claude や Codex の 5 時間・週の上限が 80% と 95% を超えたときに一度ずつ知らせ、そこまで使った上限がリセットされたときにも知らせます。初期設定でオンで、設定 → 通知 → AI 使用量でオフにできます。
- **エージェントとターミナルからの通知。** Claude Code、Codex、Gemini CLI、GitHub Copilot、Antigravity、Cursor、OpenCode のフック、omp・omo・pi の拡張機能、Hermes・Amp のプラグイン、Muxy 2・cmux・herdr・Paseo 内のエージェント、tmux や WezTerm のベルがノッチに表示されます。通知をクリックすると、そのターミナル、ペイン、タブが前面に出ます([設定方法は下記](#エージェントとターミナルの通知))。
- **権限の確認と質問。** Claude Code が実行や編集の許可を求めると、ノッチから許可、拒否、常に許可を選べます。「常に許可」は、Claude Code が規則を提案したとき、またはワイルドカードや連結記号のない単純なシェルコマンドなら、そのコマンドだけを許可する規則として表示されます。どちらの場合も、規則が普通のキーボード文字(印字可能な ASCII)だけでカードに収まるときに限ります。カードにはツール、フォルダ、すべての項目が表示され、英字や記号に見間違えそうな文字がテキストに含まれていると、オレンジの「普通でない文字」チップで知らせます。Codex のコマンド、ファイルの編集(`apply_patch` は対象ファイルを一覧表示)、MCP ツールの承認も同じように扱え、「常に許可」の代わりに「ターミナルで答える」が出ます。OpenCode の権限の確認も同様で、Paseo のツールの承認も同じように扱えますが、「ターミナルで答える」の代わりに「Paseo で答える」が出ます。GitHub Copilot、Antigravity(コマンドとファイルの書き込み)、Cursor(シェルコマンドと MCP 呼び出し)の承認も同じように扱え、Cursor は「Cursor で答える」が出ます。何が実行されるかに少しでも曖昧さが残る要求(たとえばサンドボックスの外で動く Cursor のシェルコマンド)にはカードを出さず、ツールが自分のプロンプトで尋ねます。Gemini CLI、Hermes、Amp はセッションと通知を表示しますが、承認は扱いません。Claude Code の質問にも答えられます。答えを 1 つまたは複数選び、質問が複数あれば順に進め、「ターミナルで答える」でターミナルに戻すこともできます。答えを正確に表示できない質問はターミナルに残ります。先にターミナルで答えるとカードは消えます。確認の内容はメモリ内にだけ残ります(設定 › 通知でオフにできます)。そのエージェントのターミナルが最前面にあるときは、すでに見ている場所なので、ノッチには出さずターミナルで尋ねさせます（設定 › 通知）。
- **通知タブ。** エージェント、ターミナル、カレンダーからの直近 30 件の通知を表示し、未読にはバッジが付きます。クリックすると送信元に戻れます。初期設定ではオフ(設定 › ノッチ)で、メモリ上にだけ保持されます。
- **眉の表情。** 眉がエージェントの様子を表情で伝えます。あなたを待っているエージェントがいれば眉尻を上げ、作業中は低く平らになります。エージェントがターンを終えると眉が2回ぴょんと跳ね、どのエージェントが終わったかをノッチが伝えます(そのターミナルがすでに前面にあれば知らせません。設定 › 通知)。Claude や Codex の上限が残り少なくなると下がり、リセットされるとまた上がります。ノッチのない画面ではアプリの眉そのものが表情を変え、ノッチのある画面ではエージェント数の横に小さな眉が出て、エージェントと上限の通知のアイコンも眉になります。「視差効果を減らす」がオンなら動きません。
- **作業中のエージェント。** 閉じたノッチに表示される項目で、入力を待っているコーディングエージェントの数(上がった眉と黄色の数字)、待っているものがなければ作業中の数(低く平らな眉と緑の数字)を示します。Claude Code、Codex、Gemini CLI、OpenCode、GitHub Copilot、Antigravity、Cursor、Hermes、Amp、omp、omo、pi はフック、プラグイン、拡張機能で対応し(設定 › 通知で接続。Codex は次の起動時にフックを信頼するか尋ねます)、gjc、herdr、Muxy 2、Paseo は接続なしで対応します。`claude --bg` で起動したバックグラウンドセッションも数えます。Claude Code がターンを終えたときにサブエージェントやバックグラウンドのシェルコマンドがまだ動いていれば、そのセッションは最長 2 時間、作業中として数えられ、エージェントタブに「バックグラウンド · タスク N件」のチップが付きます。
- **エージェントタブ。** 作業中、または入力を待っているコーディングエージェントのセッションを、1 件につき 1 行で一覧します。対象は Claude Code、Codex、Gemini CLI、OpenCode、GitHub Copilot、Antigravity、Cursor、Hermes、Amp、omp、omo、pi、gjc、Paseo、そして herdr や Muxy 2 の中で動くエージェントです。状態は色だけでなく形でも区別できます。入力待ちは塗りつぶしのオレンジの点、作業中は回る緑の弧、待機中は空の輪です。続いて、名前(Claude Code の `/rename` の名前か自動のタイトル、Codex のスレッド名)、フォルダ、ツールとモデル、標準以外の権限モードのチップ、トークン数つきの小さなコンテキストメーター、その状態になってからの経過時間が並びます。どの行にも「ターミナルへ」(Paseo の行は「Paseo で開く」)と「メッセージ」のボタンがあり、破線のボタンは今は使えないことを示し、ツールチップが理由を教えてくれます。入力を待っているセッションは行が開いて「ターミナルで答える」が表示されます。一番下の行は状態の件数をまとめます(「入力待ち 1 · 作業中 3 · 待機中 1」)。キーボードは ↑↓ で選択、↵ でターミナルへ移動、⌘M でメッセージ欄を開き、行をダブルクリックしてもターミナルへ移動します。直近 3 時間に使った開いたままのセッションは薄く「待機中」と表示されます(閉じたノッチの数には含めません)。開いているセッションが 1 つもないときは、「最近」に開いていない過去 1 週間の会話が最大 5 件並び、クリックするか ↵ を押すと、設定 › 通知で選んだターミナルで再開します(`claude --resume`、`codex resume`、または各ツール独自のオプション)。この Mac にあるツール自身のセッションファイルから、フォルダ、モデル、トークン数、権限モード、セッション名、直近のプロンプトを読み取ります。 作業中またはターンを終えたセッションの下には、直前の作業が表示されます。読んだり編集したりしたファイル、実行したコマンド、尋ねた質問です。編集なら +N −M と **差分を見る** が付き、押すと一覧の代わりに変更行が表示されます(← → でこのターンの他の変更、Esc で戻る)。作業中のセッションがタブに表示されている間は、セッションファイルを2秒ごとに確認します。
- **セッションにメッセージを送る、ファイルをドロップする。** 行の「メッセージ」ボタン(または ⌘M)を押すと、一番下の行がそのセッションを「宛先」にした入力欄に変わり、Return を押すとテキストがそのセッションの入力に入って Return まで送られます。Esc でキャンセルです。シェルフや Finder からファイルを行にドロップすると、そのパスが Return なしで入力され、シェルフからドラッグするときは、エージェントタブのボタンの上にポインタを置くとタブが切り替わります。Ghostty、Terminal、iTerm2、WezTerm、kitty、cmux、herdr、Muxy 2、Orca のセッションで使えます(Terminal はメッセージのみで、ファイルは受け付けません)。Paseo は作業中でないエージェントへのメッセージのみです(下の「どこで何ができるか」の表)。許可の確認や質問が開いている可能性があるとき、tmux・zellij・screen の中のセッション、どのターミナルにいるか確認できないセッションには、何も送りません。
- **週間まとめ。** 週が変わって(月曜日以降)最初にノッチを開くと、「先週、眉が見ていたこと」というカードが表示されます。エージェントの作業時間(前の週との比較つき)、ツールごとのセッション数、変更した行(+/−)とファイル数、ツールごとのトークン、最も作業したプロジェクトとその割合、最も長いセッション、最も忙しかった日(棒グラフ)が並びます。Claude Code、Codex、omo、gjc、omp、pi、OpenCode のセッションファイルからこの Mac の中だけで集計し、どこにも送信しません。プログラムが Agent SDK で開始したセッションは含みません。**画像を保存**を押すと、プロジェクト名を伏せた 1080×1920 の PNG がダウンロードフォルダに書き出されます。AI 使用量タブの「先週」からいつでも開き直せます。初期設定でオンで、設定 › 通知 › AI 使用量でオフにできます。

**🧩 自分好みに**
- すべてのタブがヘッダの 1 行に収まり、現在のタブは名前がカプセルの中に表示されます。ノッチのある画面では、この行はカメラの左側に置かれ、収まらないときはスクロールします。ホーム、タイマー、ツール、システム、AI 使用量は、大きな数字と細いバーのパネルで構成されています。設定にはサイドバーがあり、ノッチのタブ一覧はドラッグで並べ替えられる 2 列のグリッドです。
- タブを選んでドラッグで並べ替え、ヘッダに日付を表示するか、閉じたノッチの表示内容、表示するポップアップを選べます。**オフにした機能は動作自体を止めます。**
- macOS 26 では、開いたノッチとカードに Liquid Glass を使い、背後がやわらかく透けて見えます。ガラスの濃さは最大 100% の真っ黒なノッチまで調整でき、ガラス表現をオフにすることもできます。
- ノッチのないディスプレイでは、閉じたノッチはメニューバーの中の小さなバーで、白い筆跡の眉が載っています(お好みでガラス調に)。ポインタを重ねると眉が持ち上がります。使われないまま一定時間(3〜60 秒、または無効)が過ぎると、眉が閉じるまぶたのように下がってフェードアウトし、ポインタが近づくと戻ります。そこに 0.5 秒とどまると、画面上端に取り付いて開きます。この場合、HUD、通知、歌詞、スニークピークは 1 行で表示され、記号はレベルバー、パーセント、テキストのすぐ横に並びます。待機中の表示は、バーを左右それぞれの値の分だけ伸ばし、値は眉のすぐ横に並びます。眉はカメラの上から動きません。
- ディスプレイ、サイズ、ホバーの待ち時間、ログイン時の自動起動、クラムシェル(蓋を閉じた状態)でのノッチ非表示を設定できます。自動にすると閉じたノッチはポインタを追って別のディスプレイへ移り、オフにすると一つの画面にとどまります。Mission Control では隠れます。
- 下にスワイプで開き、上にスワイプで閉じ、ホームで横にスワイプすると曲をスキップできます。
- English、한국어、日本語、简体中文、Español、Deutsch、Français に対応し、Mac の言語設定に従います。

## FAQ

<details>
<summary><b>macOS に「Nunsseop は開けません」と表示されます。</b></summary>

0.37.0 からは Apple の署名と公証を受けていて、ほかのアプリと同じように開けます。それより古いバージョンは公証前のものです。[最新の DMG](https://github.com/namekun/Nunsseop/releases/latest/download/Nunsseop.dmg) をダウンロードし直すか、Homebrew でアップデート(`brew update && brew upgrade --cask nunsseop`)してください。
</details>

<details>
<summary><b>Dynamic Island のある MacBook Pro でも動きますか？</b></summary>

動くはずですが、実機ではまだ試せていません。Dynamic Island はシステムが描く場所なので、眉はその上ではなく横に置かれ、ポインターを合わせるといつもどおり開きます。お持ちの方は `/Applications/Nunsseop.app/Contents/MacOS/Nunsseop --print-screen-info` を実行し、結果を [Issue](https://github.com/namekun/Nunsseop/issues) で送ってください。その値をもとに調整します。
</details>

<details>
<summary><b>音楽を再生しても何も表示されません。</b></summary>

Nunsseop は、macOS が「再生中」として認識している内容を表示します。そのため、プレーヤーがコントロールセンターに表示される必要があります。ほとんどのアプリとブラウザは表示されます。代替手段については、[再生中情報の取得方法](#再生中情報の取得方法)をご覧ください。
</details>

<details>
<summary><b>検索で Spotlight を置き換えられますか?</b></summary>

はい。設定 → 一般を開き、ショートカットをクリックして <kbd>⌘Space</kbd> を押してください。Spotlight が使っていることを Nunsseop が知らせ、キーボードショートカットを開くので、そこで「*Spotlight 検索を表示*」のチェックを外します。検索タブを非表示にしていても、検索は開きます。
</details>

<details>
<summary><b>タブが多すぎます。</b></summary>

ノッチを右クリック → 設定 → ノッチで、不要なものをオフにしてください。オフにした機能は完全に動作を止めます。
</details>

<details>
<summary><b>お使いの Mac にノッチがありません。</b></summary>

蓋を閉じた状態の外部モニタなど、ノッチのないディスプレイでは、閉じたノッチはメニューバーの中に浮かぶ、白い筆跡の眉が載った小さなバーになります。ポインタを重ねると眉が持ち上がり、開くとノッチが通常のサイズで画面上端に取り付きます。HUD、通知、歌詞、スニークピークは、カメラの周りではなく 1 行で表示されます。使われないときは、眉が閉じるまぶたのように下がり、バーがフェードアウトします。オフにしたり、待ち時間を変えたりするには、設定から行えます。ディスプレイが複数あるときは、閉じたノッチはポインタのあるディスプレイに移動します。移動するのは閉じ終わってからで、HUD、承認、プレビューもそのディスプレイに表示されます。設定でディスプレイを 1 つ選ぶと、そのディスプレイに留まります。
</details>

<details>
<summary><b>AI 使用量に古い Claude の上限が表示されるのはなぜですか?</b></summary>

初期設定では、Claude の 5 時間と週のパーセンテージは、他のツールが書き込むキャッシュから取得されます。ターミナルで Claude Code を使っている間の [oh-my-claudecode](https://github.com/Yeachan-Heo/oh-my-claudecode) の HUD、または gjc が書き込んだものです。カードには最終更新時刻が表示されます。上限を最新に保つには、設定 › サービス › AI 使用量で Claude Code のステータスラインを接続してください。Claude Code が応答のたびに上限を渡し、これまでのステータスラインもそのまま使えます。Claude を別の場所で使う場合は、代わりに AI タブまたは設定 › サービスで、Claude の上限のリアルタイム取得をオンにしてください。いちばん新しい取得元が優先され、そこにプランやモデル別のバーがなければ前のものをそのまま表示します。トークンの合計は常に最新です。
</details>

<details>
<summary><b>アップデート後、音量キーで Nunsseop の HUD が出なくなりました。</b></summary>

0.8.3 より前のバージョンは、アップデートのたびに macOS がアクセシビリティの許可を忘れてしまう署名方法でした。0.8.3 以降は許可が保持されます。古いバージョンからアップデートした場合は、システム設定 → プライバシーとセキュリティ → アクセシビリティから一度 Nunsseop を削除し、もう一度許可してください。再起動しなくても反映されます。
</details>

## エージェントとターミナルの通知

Nunsseop は `127.0.0.1:47750` で、Mac 上のツールからの通知を待ち受けます。リクエストには、`~/Library/Application Support/Nunsseop/notify-token` に保存されたシークレットトークンが必要です。

設定 → 通知を開き、Claude Code、Codex、Gemini CLI、GitHub Copilot、Antigravity、Cursor、OpenCode、Hermes、Amp、omp、omo、pi の横にある**接続**を押します。この Mac で使ったことのあるツールだけが一覧に表示されます。Nunsseop はそのツールの設定ファイル(`~/.claude/settings.json`、`~/.codex/config.toml`、`~/.codex/hooks.json`、`~/.gemini/settings.json`)を書き換えるか、`~/.config/opencode/plugins` にプラグインを、`~/.omp/agent/extensions` に小さな拡張機能を追加し(omo と pi も同様に `~/.omo`、`~/.pi`)、元のファイルは拡張子 `.nunsseop-backup` を付けて残します。 何かを書き込む前に、ファイルがどう変わるか(追加される行は緑、取り除かれる行は赤、変わらない部分は折りたたみ)と、どのバックアップが残るかをシートで表示します。**キャンセル**すると何も書き込みません。ファイルが他のツールと共有されている場合(Claude Code、Codex、Gemini CLI、Antigravity、Cursor)、もともとあったフックはそのまま残り、**接続解除**で取り除かれるのは Nunsseop のものだけです。Codex は `notify` コマンドを 1 つしか使えないため、すでにあるコマンドは Nunsseop のコマンドの後に実行されます。作業中のエージェント数のためのフックは、他のツールのフックと並べて `~/.codex/hooks.json` に入り、Codex は次の起動時に信頼するか尋ねます(「Review hooks」なら Nunsseop のものだけを信頼でき、「Trust all and continue」はすべてのツールの新しいフックを信頼します)。それまでは実行されず、フックの文面が変わる更新のあとには、もう一度尋ねます。ノッチで承認に答えるためのフックも同じように信頼が必要で、以前に接続していた場合は Codex がもう一度尋ねるので、/hooks で確認してください。**接続解除**で元に戻せます。その後に開始したセッションの通知が、ノッチに送られます。gjc は接続不要です。エージェントの数やエージェントタブが表示されている間、gjc 自身のファイルからセッションを読み取ります。

GitHub Copilot には専用のフックファイル `~/.copilot/hooks/nunsseop.json` が、Antigravity(`agy` コマンドライン)には `~/.gemini/config/hooks.json` に 1 件のエントリが、Cursor には `~/.cursor/hooks.json` にエントリが、他のツールのフックと並んで入ります。Hermes と Amp には Nunsseop のプラグイン(`~/.hermes/plugins/nunsseop`、`~/.config/amp/plugins/nunsseop.ts`)が入ります。Hermes はターミナルで `hermes plugins enable nunsseop` を一度実行するまでプラグインを読み込まず、設定にはそのコマンドと、Hermes で有効かどうかが表示されます。Amp のプラグイン API は実験的なので、Amp のアップデートで動かなくなることがあります。接続すると、Gemini CLI、GitHub Copilot、Antigravity、Cursor、Hermes、Amp はセッションをエージェント数とエージェントタブに知らせ、ターンが終わると通知を送ります。GitHub Copilot、Antigravity、Cursor の承認は、設定 › 通知の「ノッチで権限の確認と質問に答える」がオンのときだけノッチに表示されます。

Claude Code を手動で設定するには、**Claude Code フックのコマンドをコピー**を押して、`~/.claude/settings.json` に追加します。

```json
{
  "hooks": {
    "Notification": [
      { "hooks": [{ "type": "command", "command": "<paste the copied command here>" }] }
    ]
  }
}
```

ターミナルやエージェントアプリには、フックは不要です。

- **Muxy 2:** Muxy 自身が検出したエージェントを、Muxy の実行中に `muxy activity list` で読み取ります。通知として表示され(Muxy が前面にあるときは表示しません)、Muxy だけが把握しているセッションは、作業中か入力待ちの間だけエージェントタブに表示されます。通知ファイルとソケットを使っていた Muxy 1 には対応していません。
- **cmux:** アプリ内の cmux コマンドを通して通知を読み取ります。cmux が前面にあるときは表示しません。
- **herdr:** すべてのセッションで、終了したエージェントや入力を待っているエージェントを、herdr のソケットから読み取ります。
- **Paseo:** 終了または失敗したエージェントを、Paseo 自身が残す記録ファイルから読み取るので、デーモンがなくても表示されます。承認カードと Paseo のイベントには、この Mac 上でパスワードなしで動いているデーモンが必要で、Nunsseop はそれを起動しません。
- **tmux:** すべてのウインドウのベルに対応します。Nunsseop は実行中の tmux サーバーにだけフックを追加し、`tmux.conf` は変更しません。
- **WezTerm:** 設定 › 通知でコピーした行を `~/.wezterm.lua` に貼り付けると、ベルに対応します。

それぞれ、ツールがインストールされている場合に限り、設定 › 通知にトグルが表示されます(WezTerm は、設定の行をコピーするボタンになります)。すでに専用のフックで接続済みのツールは、重複して表示されません。Orca には独自の通知元がなく、そのセッションは、上で接続したフックや拡張機能(Claude Code、Codex、OpenCode、pi など)が Orca のペイン ID を送ってきたときだけ表示されます。

スクリプトからも通知を送れます。

```sh
# notify-auth には Authorization ヘッダーが入っているので、トークンがプロセス一覧に表示されません。
curl -X POST http://127.0.0.1:47750/notify \
  -H @"$HOME/Library/Application Support/Nunsseop/notify-auth" \
  -d '{"title": "Build", "message": "Finished in 42 s"}'
```

### どこで何ができるか

行の「ターミナルへ」「メッセージ」ボタンとファイルのドロップは、そのセッションがどのターミナルにいるかを Nunsseop が確かめられる場所で動きます。セッションのプロセスが本当にそこで動いているかを確認します。テキストはターミナル自身の入力 API を通して入り、擬似的なキー入力で送ることはありません。メッセージやファイルのドロップができない場合はボタンが破線になり、ツールチップが理由を教えます(tmux・zellij・screen が間にある、回答待ちの確認がある、同じフォルダに Ghostty のタブが複数ある、など)。その場合も「ターミナルへ」はターミナルアプリを前面に出します。

| ターミナル | タブ・ペインへ移動 | メッセージ | ファイルのドロップ | 「最近」から再開 |
| --- | :---: | :---: | :---: | :---: |
| Ghostty | ✓¹ | ✓¹ | ✓¹ | ✓ |
| Terminal | ✓ | ✓ | — | ✓ |
| iTerm2 | ✓ | ✓ | ✓ | ✓ |
| WezTerm | ✓ | ✓ | ✓ | ✓ |
| kitty | ✓ | ✓ | ✓ | ✓ |
| cmux | ✓ | ✓ | ✓ | ✓ |
| herdr | ✓ | ✓ | ✓ | — |
| Muxy 2 | ✓ | ✓ | ✓ | ✓ |
| Orca | ✓ | ✓ | ✓ | ✓ |
| Paseo | ✓ | ✓ | — | ✓ |

¹ Claude Code のセッションのみ。

- **Ghostty、Terminal、iTerm2** は AppleScript で操作するため、macOS が Nunsseop にそれぞれの操作を許可するかを一度ずつ尋ねます(システム設定 › プライバシーとセキュリティ › オートメーション)。Ghostty は自分のタブがどれかをシェルに教えないので、Nunsseop はセッションのフォルダと Claude Code がタブに付けるタイトルからタブを選ぶため、タブへの移動、メッセージ、ファイルのドロップは Claude Code のセッションでだけ使えます。確実にどのタブか分からないときは何も送りません。Terminal は実行されるテキストしか受け取れないため、メッセージは送れますが、ドロップしたファイルは受け付けません。
- **WezTerm と kitty** はコマンドラインツール(`wezterm cli`、`kitty @`)で操作します。kitty はリモートコントロールをオンにし、待ち受けるソケットを用意しておく必要があります。
- **Muxy 2:** セッションのペインに正確に移動し、新しいタブで会話を再開するには、Nunsseop の小さなブリッジ拡張機能を一度読み込みます。Muxy で Settings › Extensions › Load Unpacked… を開き、`~/Library/Application Support/Nunsseop/muxy-bridge` フォルダを選んで(設定 › 通知の「Finder で拡張機能を表示」でそのフォルダを開けます)、拡張機能をオンにしてください。読み込まない場合、クリックではセッションのプロジェクトが選ばれるだけです。フックがなく Muxy だけが把握しているセッションには移動はできますが、テキストは送れません。
- **Orca:** `orca` コマンドラインで操作します。最近の会話は、Orca にウインドウがある間、その会話を含むワークツリーの新しいタブで再開されます。
- **Paseo:** メッセージは `paseo send` で送られ、作業中のエージェントは中断されてしまうため、作業中でないエージェント(終了したものや入力待ちのものを含む)にだけ送れます。クリックすると Paseo でそのエージェントが開き(表の最初の列はこの動作です)、アーカイブ済みのエージェントは「最近」から戻せます。
- **再開**は、設定 › 通知の「会話を再開するターミナル」で選んだターミナルで行われ、使えないときは Terminal が代わりになります。Ghostty、iTerm2、cmux はインストールされていれば候補に出て、起動していなければ起動します。WezTerm はコマンドラインツールがあるとき、kitty はそのセッションが知らせたソケットがまだあるときだけ、Orca はウインドウがあり、Orca がワークツリーとして把握しているフォルダのときだけ(違えば次のターミナルへ回ります)、Muxy はブリッジが動いているときだけ候補に出ます。Ghostty と iTerm2 はオートメーションで新しいタブを開き(Ghostty は許可がなければ新しいウインドウ)、cmux はタブではなく新しいワークスペースを開きます。Paseo の「最近」の項目はこの設定に関係なく Paseo で開きます。

## 権限

Nunsseop は、ほとんどの権限を、それを必要とする機能を初めて使うときに求めます。例外は、スクリーンショット(標準ではデスクトップ、または設定したスクリーンショットのフォルダ)とダウンロードを監視するフォルダで、Nunsseop の初回起動時に macOS が尋ねることがあります。

| 機能 | 権限 | 許可を求めるタイミング |
| --- | --- | --- |
| カレンダー | カレンダー | ホームタブで*アクセスを許可*を押したとき |
| リマインダー | リマインダー | ホームタブで*リマインダーを許可*を押したとき |
| ミラー | カメラ | ミラータブで*カメラを許可*を押したとき |
| 画面収録、他のアプリのウインドウからのテキストコピー | 画面収録 | 初めて録画またはテキストの取得を始めたとき |
| 音声付きの録画 | マイク | 初めてマイク音声をオンにして録画したとき |
| 音量、明るさ、キーボードバックライトキーの横取り | アクセシビリティ | 設定でそのオプションをオンにしたとき |
| ミュージック、Spotify、ブラウザの再生中情報の代替取得 | オートメーション | MediaRemote ヘルパーが使えない場合のみ |
| ブラウザでの Google Meet、Zoom、Teams の通話表示、Meet のマイク・カメラのボタン | オートメーション(そのブラウザ) | ブラウザが初めてマイクを使ったとき |
| シェルフへの新しいスクリーンショットの追加、ダウンロードの通知 | デスクトップとダウンロードのフォルダ | Nunsseop の初回起動時に macOS が尋ねることがあります(スクリーンショットのフォルダ(標準ではデスクトップ)とダウンロードフォルダを監視します) |
| アプリごとの音量 | システムオーディオの録音 | ツールタブで初めてアプリの音量を下げたとき |
| Zoom と FaceTime の通話でのミュートのボタン、Zoom のカメラのボタン | アクセシビリティ | 自分から許可を求めることはありません。Nunsseop にアクセシビリティが許可されていればボタンが表示されます(上の音量キーのオプションで許可することもできます) |
| エージェントセッションへのメッセージ入力、セッションのタブへの移動、新しいタブでの会話の再開(iTerm2 と Ghostty のみ) | オートメーション(Terminal、iTerm2、Ghostty) | そのアプリで初めて行ったとき。Ghostty は、エージェントタブに Ghostty 内のセッションが初めて表示されたときにも |
| ログイン時に開く | ログイン項目 | 設定でオンにしたとき |

## プライバシー

Nunsseop は個人データを収集も送信もしません。オンラインに接続するのは、次の場合だけです。

- `api.github.com` で、新しいリリースがないかを 1 日 1 回確認します(オフにできます)。DMG からインストールしたアプリでアップデートをインストールするときは、GitHub から最新リリースの `appcast.xml` と DMG を取得します。
- `lrclib.net` で、同期歌詞を検索します(オフにできます)。
- 入力した都市の天気を `open-meteo.com` から取得します(都市を入力するまではオフ)。Open-Meteo で見つからない場合は、都市の位置を Apple のジオコーダに問い合わせます。
- MediaRemote ヘルパーが使えない場合に限り、既知の音楽サービスから HTTPS でアートワークをダウンロードします。
- Claude の上限のリアルタイム取得をオンにした場合に限り、キーチェーンにある Claude Code のサインイン情報を使って、約 1 時間ごとに `api.anthropic.com` へ上限を問い合わせます。

それ以外はすべて Mac の中にとどまります。通知サーバーは、この Mac からの接続しか受け付けません。AI 使用量は、Claude の上限のリアルタイム取得をオンにしない限り、Claude Code のステータスラインがこの Mac に保存する上限を含め、ローカルのファイルから読み取ります。通知タブの通知は、メモリ上にだけ保持されます。録画はスクリーンショットの保存先に保存されます。カメラのプレビューはミラータブを開いている間だけ動作し、録画されることはありません。クリップボード履歴は、Nunsseop を終了すると消去されます。

## 再生中情報の取得方法

macOS 15.4 以降、非公開の MediaRemote フレームワークは Apple が署名したプロセスにしか応答しません。そこで Nunsseop は小さなヘルパーライブラリ(`Sources/NowPlayingHelper`)を同梱し、システムの `/usr/bin/perl` の中で実行して、再生中の状態を読み取り、再生、一時停止、スキップ、シークのコマンドを送り、JSON の行をアプリにストリームで返しています。

これは非公開 API に依存しているため、今後の macOS アップデートで動かなくなる可能性があります。その場合、Nunsseop はミュージックと Spotify には AppleScript を、ブラウザにはメディアタブの読み取りを代替手段として使います。この代替手段には、各ブラウザで「*Apple Events からの JavaScript を許可*」をオンにする必要があります。Dia にはそのメニュー項目がないため、Nunsseop が `--enable-applescript-javascript` を付けた再起動を提案します。

## ソースからビルド

```sh
git clone https://github.com/namekun/Nunsseop.git
cd Nunsseop
./scripts/bundle.sh release      # build/Nunsseop.app
./scripts/make-dmg.sh            # build/Nunsseop-<version>.dmg
```

Swift 5.10 以降を含む Xcode コマンドラインツールが必要です。`scripts/bundle.sh` は Swift パッケージをビルドし、アドホック署名のアプリバンドルにまとめます。
